# Jinshi rank-encoding audit

Generated by `scripts/audit_jinshi_encoding.py`. Aggregate counts only; no individual records are exported.

Raw export: `明进士.xlsx` — 28,761 rows, 27,711 unique CBDB `PersonID`.

## Why this file exists

The published figure pipeline selected elite Jinshi with the literal regex
`第1甲|第2甲`. CBDB writes the same rank in two numeral systems:

| Encoding | Example | Matches the old regex |
|---|---|---|
| Arabic | `第1甲第3名` | yes |
| Chinese | `第一甲第三名` | **no** |

The 911-record layer is therefore a *format-selected* subsample. This audit quantifies the bias and gives the corrected denominator.

| 0 records of 3甲 | 3甲 is excluded by design (`is_important` keeps 1甲/2甲) |

| Cluster sizes of exactly 100 | `max_cluster_size=100` truncates dense clusters |

## 6. Corrected numbers to use

- Elite Jinshi in 1521–1619: **2,855 confirmed lower bound** (2,853 strict
  regex; 2,841 with coordinates). 武舉 rows in the window are all unparsed, so
  the layer is civil-only; see
  [`jinshi_unparsed_audit.md`](jinshi_unparsed_audit.md).
- The 911 layer is **not** a random sample and **not** a rank-complete sample.
- It is retained only as an audit; the v0.3 figures use the normalized elite
  (2,841). The direct sensitivity check is in
  [`corrected_robustness.md`](corrected_robustness.md).

## 7. Normalization rule

```python
RANK_RE = re.compile(r'^\s*(?:第)?\s*([一二三123])\s*甲')
```

Apply this before filtering; never match the literal string `第1甲` alone.
